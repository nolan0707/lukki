Claude Code 的 Bash 安全沙箱是其“Harness（治理框架）”设计中最核心的安全防线之一。根据泄露的源码分析，这一机制并非简单的字符串过滤，而是一个深度集成在 BashTool 中、基于 AST（抽象语法树）分析的复杂验证系统。
以下是该沙箱实现机制的深度拆解：
1. 核心底座：基于 AST 的静态指令分析
与传统工具使用正则表达式（Regex）匹配敏感词不同，Claude Code 在 utils/bash/ 目录下构建了超过 2,500 行的逻辑，专门用于在指令执行前进行深层解析。
语法树解析：系统内置了一个完整的 Shell AST 解析器。在任何命令发送到终端执行前，它会先将命令分解为语法树结构，从而识别指令的真实意图。
语义拦截而非关键字匹配：通过分析 AST，它能准确识别复杂的混淆攻击或嵌套指令（如 curl | bash 或 sudo 提权），这是普通正则匹配无法实现的深度防御。
2. 深度防御：严密的指令限制清单
该沙箱明确拦截了一系列具有潜在破坏性或恶意企图的指令和模式：
破坏性操作拦截：严禁执行如 rm -rf / 等可能导致系统损毁的指令。
资源溢出保护：专门拦截 Fork Bomb（派生炸弹）等试图通过无限复制进程导致系统崩溃的行为。
提权与注入防御：拦截 sudo 等提权尝试，以及 TTY 注入和历史记录操纵等旨在获取持久化控制权或抹除痕迹的操作。
时间预算控制：沙箱甚至会对耗时指令进行限制，例如明确禁止执行 sleep N（其中 N ≥ 2 秒），防止模型通过长时间阻塞操作占用系统资源。
3. 多级权限治理体系
沙箱的运行受到一个 三层权限模型 和 六种权限模式 的严格约束：
风险分级（Risk Classification）：每一项工具操作都被标记为 LOW、MEDIUM 或 HIGH 风险级别。Bash 指令通常属于高风险操作，需要更严苛的审核。
预检流程（Pre-flight Check）：QueryEngine 在调用工具前会执行 validateInput() 确保参数符合 Zod 模式校验（防止输入格式漏洞），随后由 checkPermissions() 处理器根据当前模式（如 default、auto 或 plan）决定是自动放行、彻底阻止还是询问用户。
保护特定资产：沙箱会自动保护敏感配置文件（如 .gitconfig、.bashrc、.zshrc 及 .claude.json），禁止模型对其进行自动编辑。
4. 路径与编码安全加固
为了应对提示词注入（Prompt Injection）和逻辑绕过，沙箱在底层执行了以下加固措施：
Unicode 规范化与净化：通过 partiallySanitizeUnicode() 函数剥离隐藏字符，防止恶意脚本通过 Unicode Smuggling（Unicode 走私攻击）绕过安全检查。
路径遍历防御：系统严密处理 URL 编码的遍历路径、反斜杠注入以及大小写敏感的路径操纵，防止模型访问信任边界外的目录。
总结
这 2,500 行代码构成的不仅是一个沙箱，更是一个具备环境感知能力的治理层。它通过“怀疑论”设计，不依赖模型自身的道德约束，而是通过强制性的静态分析（AST）和运行时权限隔离，将 AI 的行为囚禁在安全的物理边界之内。
